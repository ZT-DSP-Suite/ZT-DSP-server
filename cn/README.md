## 为什么需要服务器版

当前客户端版（仓库 `ZT-DSP-client`）是直连模型：通信双方必须各自可达——**两端都需要公网 IP 或其他可直连方式**（端口映射、IPv6、隧道等）。这在小规模、互信的朋友之间可用，但不适合以下场景：

- 一方位于 NAT 之后且无法做端口映射；
- 需要异步投递（对方离线时消息仍能送达）；
- 需要多方群组、身份目录或跨组织联邦；
- 需要在不暴露彼此 IP 的前提下建立连接。

服务器版的目标是在**不削弱现有端到端安全属性**的前提下补齐上述能力，并保持与客户端版协议的兼容与可互操作。

## 状态

- 阶段：**规格设计前**
- 本仓库当前只包含占位说明与许可。功能范围、协议扩展、威胁模型与安全边界将在设计文档确定后逐步填入。
- 服务器**不得**成为明文可见点：任何中继设计都必须保持端到端加密，服务器应仅能看到路由所需的最小元数据。

### 适用关系（多对多）

总指导版本与客户端/服务端版本之间**不是**一对一，而是多对多：

| 关系 | 规则 |
|---|---|
| 一个总指导版本 → 多个实现版本 | 同类实现只要**协议行为未变**就**共用一条声明**，不必按版本重写 |
| 多个总指导版本 → 一个实现版本 | 一个实现可同时适用多份指导；在 `APPLIES_TO_DOC_VERSIONS` 里逐项列出 |
| 版本号相同、实现不同 | **版本号相同不等于实现相同，也不构成任何兼容性主张** |
| 兼容性怎么判定 | 适用关系是**声明**不是测试；真实兼容始终由阶段三确认标签检查给出 |

握手帧**不携带版本串**：阶段一参数 JSON 与阶段四 AAD 都不含版本或协议标识字段。

> 本仓库尚无实现。上面的 `ZT-DSP_SV-1.0.0` 是为承载适用关系而预留的**占位标识**，不是已发布的实现。
